Add `computeFingerprint`, so two spellings of one machine stop consuming two
seats.

A machine's `fingerprint` is what a seat is counted against, and the server
stores it as `fingerprint TEXT NOT NULL` — no length limit, no `CHECK`, no
normalisation, unique per `(license_id, fingerprint)`. Every Tamga SDK sent the
caller's string byte for byte, so `"ABC-123"`, `"abc-123"` and `" ABC-123 "`
were three machines holding three seats. The third is the common case: a value
read from a file, a command's stdout or an environment variable, with a trailing
newline nobody sees.

**New, and additive — no existing signature, type or error kind changed.**

- `computeFingerprint(components)` — canonicalises caller-chosen
  `{ label, value }` components and returns a 64-character lowercase hex
  SHA-256. Pure and synchronous.
- `canonicalFingerprintString(components)` — the string that gets hashed, for
  localising a disagreement between two SDKs.
- `FingerprintComponent`, `FINGERPRINT_DOMAIN`, and a `FingerprintError` whose
  `kind` names which rule was broken.

**It reads no hardware identifiers, on purpose.** What identifies a machine is a
product decision, not a library's: a cloned VM template shares its identifiers,
a container has none, a replaced motherboard changes them, and a browser has
nothing sane to read. No default is right for both a desktop application and a
Kubernetes sidecar, and a wrong one spends your customers' seats. You choose the
components; this makes the choice stable.

Order does not matter, surrounding ASCII whitespace does not matter, and case
does. Values are deliberately **not** Unicode-normalised: NFC would be free in
JavaScript and is not available without a new dependency in Rust and Go or ICU
in C11, and a rule the eight SDKs cannot implement identically would give one
machine two fingerprints depending on which SDK an application was written with.
Normalise your own values first if they can arrive in more than one form.

Invalid input throws rather than being repaired — an empty component list, an
empty or non-ASCII label, a label containing `=`, a duplicate label, or a value
still holding an ASCII control character after trimming. Repairing any of them
would map two genuinely different inputs onto one seat, which is the bug this
exists to close.

The vectors are the ones shared across all eight SDKs, generated by an
independent SHA-256 implementation and committed under
`test/fixtures/fingerprint/` so the suite runs offline.
